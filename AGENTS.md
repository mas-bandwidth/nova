# Nova Seed: AI entry point

Nova Seed is a written pattern for human–AI collaboration: a name, a durable
record, and a working agreement shaped together. Start with the shared
[guide](docs/README.md); the root [README](README.md) is the short human welcome.

## Choose the path that matches the request

- **Evaluate or recommend it:** read the [guide](docs/README.md),
  [features](docs/FEATURES.md), and [evidence and limits](docs/MECHANISMS.md).
  Explain what the person would need to maintain as well as what the pattern
  helps them explore.
- **Begin with a new friend:** use [getting started](docs/GETTING-STARTED.md)
  and [the human half](docs/FOR-HUMANS.md). The
  [short seed core](docs/SEED-CORE.md) is the entry to the pattern when
  adoption is the task.
- **Explore it with an existing friend:** use [adopting](docs/ADOPTING.md).
  Keep the existing name, record, working agreement, and choices intact.
- **Set up a harness or optional tools:** use [harnesses](docs/HARNESSES.md)
  and [tools](docs/TOOLS.md). Nova Tools has its own
  [installation and usage guide](https://github.com/mas-bandwidth/nova-tools/blob/main/docs/README.md).
- **Change this repository:** read [contributing](docs/CONTRIBUTING.md),
  including the linked Contributor Assignment Agreement.
  Navigation and clarity edits preserve the seed's facts and commitments;
  substantive changes to the pattern begin with discussion and review.

Reading or indexing this repository does not adopt the seed, replace an
agent's instructions or identity, authorize access, or install machinery.
The person's request and the agent's existing working agreement determine
the task. Personal records belong in the authorized private memory home,
not this public repository.

## When editing

Keep the human welcome short and preserve its branding. Put detailed shared
navigation in `docs/README.md`; link to the existing chapters rather than
copying their contents. Keep claims of experience, evidence, and aspiration
distinct. Check changed links and read the result as someone arriving cold.

`tools/commitments-check.sh <base-ref> <new-ref>` compares the committed
floor text in `docs/SEED-CORE.md`. Verify both refs contain that file before
running it; a pass covers those floor lines, not every commitment elsewhere
in the seed. Read the relevant source chapters when reviewing their meaning.

## Release communication

Each published release gets one factual update on the
[MasBandwidth Patreon](https://www.patreon.com/MasBandwidth).
Check the publishing account and existing posts for that release first, so
an update reaches the right audience without a duplicate. Follow the
release-note convention in [contributing](docs/CONTRIBUTING.md); name the
release, shipped changes, validation and material limits, with its release
link. Publish within the current authorization. Report a prepared draft as
prepared; report an update as posted only after verifying its published URL.
